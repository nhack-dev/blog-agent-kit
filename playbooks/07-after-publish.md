# 07 公開後の振り返り（Search Console・任意）

## 初回の準備（15分・オーナーの画面操作が要る）
1. Search Console にサイトを登録してあること（所有者の確認まで済んでいること）。
2. Google Cloud コンソールで新しいプロジェクトを作る（無料）。
3. 「API とサービス」→「ライブラリ」で **Google Search Console API** を有効にする。
4. 「OAuth 同意画面」を作る（種類は外部・テストユーザーに自分の Google アカウントを足す）。
5. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ 種類は **デスクトップ アプリ**。
6. 出てきたクライアント ID とシークレットを `.env` の `GSC_CLIENT_ID` `GSC_CLIENT_SECRET` に書く。
7. `python3 scripts/gsc_auth.py --go` → ブラウザで許可 → 出てきた `GSC_REFRESH_TOKEN=...` を `.env` に貼る。
8. `GSC_SITE_URL` に、Search Console に登録した形のまま書く（`https://example.com/` または `sc-domain:example.com`）。

- 権限は読み取りだけです（`webmasters.readonly`）。
- 同意画面が「テスト」のままだと、鍵が一定期間で切れることがあります。切れたら 7 をやり直します。

## 毎回（公開から2〜4週間後・その後は月1回）
```bash
python3 scripts/gsc_report.py --go --page https://example.com/<slug>/
```
- 数字は数日遅れて確定します。道具は今日の3日前までを使います。
- 出たファイル（`out/gsc-*.md`）を読み、次を `research/<slug>-review.md` に書く：

| 見る所 | すること |
|---|---|
| 伸びしろ（平均 8〜20 位） | その語の答えが記事に足りているか。足りなければ見出しか段落を足す案を出す |
| タイトルの直し候補（表示が多くクリック率が低い） | タイトル・説明文の案を2つ出す |
| 思っていない語で表示されている | 新しい記事のテーマ候補にする |

- 直す案はオーナーに出す。公開済みの記事は道具で書き換えない（オーナーが画面で直す）。
- 仮説 → 直す → 4週間後に同じ道具で前後を比べる。比べるときは期間の長さをそろえる。
