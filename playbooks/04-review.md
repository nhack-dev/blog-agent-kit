# 04 推敲

`templates/review-checklist.md` を上から順に見て、全部に印がつけば終わり。ここでは考え方を書く。

## 1. 事実の確認
- 記事の中の「事実」に下線を引くつもりで1つずつ見る：数字・日付・料金・制度・仕様・人や会社の発言。
- それぞれに出どころがあるか。出どころは**公式**か（官公庁・運営元・メーカー・論文）。まとめサイトや他のブログは出どころにしない。
- 出どころが見つからないものは消す。「〜と言われています」でぼかして残さない。
- 料金・キャンペーン・アプリの画面は変わる。確かめた日を書く。

## 2. 読みやすさ
- 声に出して読んで詰まる所を直す（エージェントは「1文が長い・主語がない・指示語が遠い」を探す）。
- 同じ文末（「〜です。〜です。〜です。」）が3回続いたら変える。
- 見出しだけ読んで話がつながるか。
- スマホの幅で、1段落が画面の半分を超えないか。

## 3. 独自の体験の入れ方
検索で上に出る記事と差がつくのは、ほとんどここです。エージェントはオーナーに**次の5つを聞き**、答えを段落にする。

1. 実際にやった（使った・買った）のはいつ・どれくらいの期間か
2. やる前に困っていたこと・迷ったこと
3. やってみて一番意外だったこと
4. 失敗したこと・合わなかったこと
5. 数字で言えること（かかった時間・費用・回数など。盛らない）

- オーナーの言葉をできるだけそのまま使う。言い換えすぎない。
- 体験が無いテーマなら、体験の段落は作らず、「わたしはまだ試していません」と正直に書くか、テーマを変える。
- 写真・画面のスクリーンショットがあれば、それが一番の証拠になる（個人情報は消す）。

## 4. 法律の入口（全記事）
- `review_check.py` の「要直し」を0件にする。
- 広告・アフィリエイトを含む記事は `08-affiliate-and-law.md` を最後まで見る。
